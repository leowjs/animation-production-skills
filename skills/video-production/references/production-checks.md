# Production checks

## Brief and sources

- Record the message, audience, output and aspect ratio, run time, language, and the visual evidence that will support the story. Infer low-impact defaults and ask when a choice changes the result materially.
- In an employee showcase, confirm the feature, workflow, outcome, and audience from the supplied evidence. Use approved screenshots or staged screens, label simulated content, and keep sensitive material out of externally hosted tools unless the user has authorized that destination.
- In a children's story, set an age-appropriate pace and use a clear goal with visible consequences. Give learners time to answer a question or act on a choice.

## Reuse and preview

- Use the relevant reference guide, examples, or source files. If using third-party code or assets, check their specific license and keep required attribution. Separate permission to read an example from permission to redistribute its code, media, or prompt.
- Check the renderer, installed dependencies, and machine constraints before a long render. Pin dependencies when reproducibility matters. Keep timing, captions, and visual cues on a common clock.
- Preview the hardest shot or branch first. Check readability at the delivery size, label placement, pace, transitions, and whether the result communicates the intended meaning.

## Delivery

- **Video:** open the rendered file or inspect representative frames. Verify duration, size, frame rate, and audio or captions as requested. Include editable source and explain how to rerender when applicable.
- **Browser story:** open it at a mobile and desktop size. Traverse each choice to an ending. Check keyboard activation, visible focus, touch targets, replay, and missing assets. Deliver the working source and launch instructions.
- **Storyboard:** return the beat sequence, style and resource choice, and the assumptions needed for production.
